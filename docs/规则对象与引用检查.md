# 规则对象与引用检查

## 本阶段范围

在第一阶段 INI/VFS 之上建立规则对象、有效字段、带类型的引用及支持清单。模型识别国家、阵营、单位、建筑、武器、弹道、弹头、动画、粒子、粒子系统、超级武器和其他已登记的类型。

公共 C 接口位于 `include/ra2/rules.h`。模型借用传入 INI 文档的字符串，先关闭模型，再关闭 INI。构建成功代表分析完成，不代表源规则无静态问题或游戏机制已实现。

## 对象与引用

- 规则节、美术节、阵营和通用前置组分别建立名称索引，避免国家 `GDI` 与阵营 `GDI` 混淆。
- 同一个规则节允许具有复合角色，例如原版国家 `Special` 被武器作为弹头名称引用，`KTSTLEXP` 同时出现在动画列表与弹头定义中。
- 从类型总表建立声明，保留没有定义的条目。武器和弹道没有独立总表，通过明确的字段形状和引用发现，不要求它们出现在不存在的类型总表中。
- 仅最后生效的重复键参与模型，旧赋值仍由第一阶段 INI 文档保留，不产生过时引用的误报。
- 检查 Primary/Secondary/ElitePrimary/EliteSecondary、数字武器槽、武器的 Projectile/Warhead、Owner/RequiredHouses/ForbiddenHouses、Prerequisite/PrerequisiteOverride 等已建模引用。
- 处理 General 中明确配置的 POWER、FACTORY、BARRACKS、RADAR、TECH、PROC 通用前置组；这里只检查成员及目标，不计算科技条件的满足关系。
- 检查部署、反部署、赠送单位、舰载机、停靠、超级武器、粒子系统及美术序列等明确关系。当前字段清单以 `src/rules_schema.c` 为准。
- 未写 Image 的实体产生同名默认映射；未找到美术节时明确标为待检查资源，不推断 SHP/VXL 一定缺失。

## 字段支持状态

| 状态 | 含义 |
|---|---|
| raw_only | 保留原文与位置，尚无专用数据解释器 |
| typed | 已进行文本、整数、数值或布尔转换；不代表游戏行为已实现 |
| reference_checked | 已按当前字段模型检查引用；具体结果见 references |
| structural_only | 类型表或通用前置组的结构信息，不冒充游戏机制 |
| not_implemented | 对应的移动、战斗、生产、绘制等运行逻辑尚未实现 |

`unimplemented_fields` 按命名空间及字段名汇总；`fields` 保留所有有效字段的原文、行号、对象、支持状态和可用的转换值。未知字段不会丢弃。仅原文保留和引用字段的 JSON `valid` 为 null，避免把未检查内容误报成数值验证通过。

标量解释按上下文区分：例如武器 Damage 为整数，而 art.ini 动画 Damage 和 Height 允许小数。百分比数值可归一化成小数，但尚未解释游戏帧、距离、速度等运行单位。

当前游戏运行字段实现数明确为零。该清单也不覆盖旧 DLL、固定地址扩展或脚本中独有而未写入 INI 的行为；中国特殊机制仍须对照既有设计和扩展记录迁移。

## 引用结果

| 状态 | 含义及处理 |
|---|---|
| resolved | 目标在当前加载的对象及类型范围中找到 |
| missing | 已建模的明确目标没有找到 |
| declared_without_definition | 类型表有声明，但缺少规则节；可能涉及内建默认值或遗留占位，单独列出 |
| wrong_type | 目标与当前模型预期类型不符，须结合规则上下文检查 |
| null | 当前字段允许空值或 none 等空引用 |
| asset_not_checked | 文件名、默认美术或动画资源尚未检查实际文件 |
| domain_not_loaded | 未加载 art.ini 等目标文档，不能判断目标是否缺失 |

这不是对引擎所有隐式默认值的完整复现。没有写出的必要字段、未建模字段中的潜在引用、科技树可达性和运行时动态分支尚未检查；不自动补全或改写原始规则。

## 命令与报告

```powershell
.\build\ra2tool.exe rules-check `
  --mix 10 'H:\开发\运行版本\原版1.006\ra2.mix|local.mix' `
  --dir 100 'H:\开发\运行版本\中国开局验证'
```

默认输出完整 JSON，成功生成报告返回 0，即使报告中有静态发现。加 `--strict` 后，明确缺失、当前模型类型不符或标量转换失败返回 2；声明未定义、未检查资源和未加载文档单独报告。运行或读取失败返回 1。

```powershell
.\scripts\verify-rules.ps1
```

脚本运行 C 测试及资源基础回归，从原版 MIX 与中国目录分别建模，并生成：

- `original.json`、`china.json`：完整对象、字段、引用和支持状态。
- `原版1.006-缺失引用.md`、`中国MOD-缺失引用.md`：明确缺失、声明未定义、类型冲突和数值问题分开列出。
- `原版1.006-未实现字段.md`、`中国MOD-未实现字段.md`：完整字段分组清单。
- `china-additional-missing.json`、`china-additional-fields.json`：相对原版的新增项，忽略来源路径和整体行号偏移。
- `validation.json`、`inputs-before.json`、`inputs-after.json`：验证结果、代码/产物哈希与源输入保存证据。

最近正式报告由 `reports/latest-rules.json` 指向。验证通过表示工具行为与输入保存检查通过，不能把报告中的已有缺失引用写成不存在。
