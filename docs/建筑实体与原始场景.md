# 建筑实体与原始场景

本文件保留模拟版本 8 阶段的实现和验收记录；当前最新版本 9 见 [建造、生产、采矿与科技](建造生产采矿与科技.md)。

更新日期：2026-10-20。后续主目标为原版 1.006 的盟苏战役与单人遭遇战，游戏菜单暂缓。当前完成二者共用的建筑与场景基础，仍不能将地图载入视作完整战役或遭遇战已经可玩。中国内容继续只保留禁用的扩展席位。

## 本阶段实现

1. 将对象与类型容量各扩展到 512，类型表由堆内存持有；最多 32 个玩家/势力，按稳定编号处理所属关系与盟友掩码。
2. 建筑共用现有的生命、装甲、目标、炮弹和摧毁系统。矩形地基占据全部相应格子，坦克不能穿过；建筑被摧毁后逐格释放，其他对象的占格不被误清除。攻击瞄准最近的地基位置，弹道碰撞和范围伤害考虑完整矩形与建筑高度。
3. 从原版规则和美术定义读取建筑 `Strength`、`Armor`、`Power`、`Image`、矩形 `Foundation` 与可带小数的 `Height`。建筑的地图局部 `Strength/Armor/Power/Image` 优先；未填写 Armor 的对象使用 none 默认值，维修屋等 Immune 对象仍禁止伤害。
4. 场景模式读取原地图的玩家、国家标识、盟友、初始金额、建筑和当前支持的 MTNK/HTNK。初始生命值按地图 0–256 比例转换，朝向和源行号保留。地图有效格不再因位于 LocalSize 镜头边界之外被直接抹去，允许保留原战役的场外初始布置。
5. 建筑实际读取 SHP 本体、地基底图、空闲/活动附加层、损坏图层，按剧场选择文件与调色板。平民建筑使用地图完整挂载中的 isotemp/isosnow/isourb 图像；不复制或修改原始资源。建筑图像和车辆共用透明像素合成及命中选择。
6. 产生与消耗电力根据当前存活建筑统计；发电量随生命比例变化，摧毁电厂会降低输出。目前是电力统计，低电力对生产、雷达和防御的完整影响尚未接入。
7. 建筑可点选查看、可成为坦克攻击目标；框选、P 全选和 N 轮选保持以可移动单位为对象。盟友建筑不会被普通左键误当敌方目标，Ctrl 强制攻击仍走既有命令路径。

`src/battle_structures.c` 实现矩形地基、建筑定义、目标位置和电力查询；`src/battle_scenario.c` 导入原地图对象与玩家；`src/structure_scene.c` 组合 SHP；`src/structurecheck.c` 输出原版场景覆盖与缺口清单。

## 查看

直接使用 `D:\Program\红色警戒2\build\ra2battle.exe`，没有 CMD 启动脚本。

- 建筑攻击验证场：`--base-demo --map MP05MW.map`。包含六座原版盟苏建筑和两辆玩家坦克，左键敌方建筑可攻击。该布置是明确的开发夹具，不是原版遭遇战开局。
- 盟军首关场景：`--scenario --map all01t.map`。
- 苏军首关场景：`--scenario --map sov01t.map`。
- 雪地战役场景：`--scenario --map all02s.map`。
- 原有桥梁演示仍为：`--bridge-demo`。

场景模式只导入已有行为的对象，不生成四辆虚构测试坦克；未实现的步兵、车辆、飞机和脚本仍保留在原始 INI，并列入报告。盟军首关中的 GI 等尚未进入本阶段运行层，因此当前无法正常完成该任务。

`ra2structurecheck.exe --corpus --validate-images` 检查全部已登记原版地图，输出对象、玩家、电力、未实现对象、建筑图像、缺失附加层，以及触发器、事件、动作、作战小队和脚本数量。`--sources <目录>` 可把原始地图与规则的只读副本写入新项目，供独立核对使用。

## 固定步与回放

固定步仍为每秒 15 步，新增建筑定义、地基状态、盟友、生命与目标共同进入规范化摘要。初始占格重建覆盖完整地基，回放不依赖显示缓存或 SHP 载入速度。

模拟版本升级为 **8**，回放标识为 **RA2RPL10**。旧版回放明确拒绝，不能按新布局误解。版本 7 的完整源码、说明、程序和资源库保存在 `build/structures-preserved`；其战场程序 SHA-256 为 `622162335b40d2bd5b1f3ade2a3d82f5024ac98634e3e6f5bf5022a60cc20989`。原始资源和其他历史备份保持不变。

## 验证与边界

复验入口：`scripts/verify-structures.ps1 -AddressSanitizer`。本次输出目录为 `reports/structures-20261020`。

测试覆盖地基重叠与边界拒绝、摧毁释放、恢复初始占格、坦克射击建筑、护甲、盟友与强制攻击、地图局部建筑覆盖、小数高度、电力变化和逐步回放。原生窗口覆盖盟苏基地的本体/损坏/摧毁、真实战役场景及雪地，并回归此前桥口坦克遮挡问题。

`scripts/verify-scenario-data.py` 独立拆分原始地图 CSV，核对导入对象的类型、所属、坐标、生命、朝向、局部建筑 Strength，以及玩家电力与盟友；检查每个未实现对象都能回溯源行，没有静默丢失。普通版和 ASAN 的完整覆盖 JSON 包括健康/损坏图像 SHA-1，可逐字节比较。

这些是新引擎使用原版资料的验证，不是原版游戏整局的逐帧验收。仍有以下边界：

- 建造、生产、部署、采矿、资金扣除、科技和胜负尚未实现。初始金额只是场景资料，不是可花费的完整经济系统。
- 建筑武器、驻军、捕获、维修、工厂出口、海空与步兵行为仍待对应模块；带 Primary 的建筑单列 `pending_weapons`，不会被伪装成已实现的坦克炮。
- 地基目前是矩形；可通行孔洞、特殊地基及部分原地图重叠布置继续列为缺口。
- MTNK/HTNK 沿用当前原版基线规则，车辆的地图局部规则合并仍待统一规则运行层。原始局部设置完整保留。
- 国家继承、国家专属科技、原版完整阵营颜色与玩家条件仍未完成；当前保留原始国家标识和关系。
- 活动动画暂以固定步驱动，尚未逐项校准 Rate/Normalized；通用美术锚点、复杂 Z 排序、阴影、驻军闪光、生产动画、残骸和倒塌仍有独立显示工作。建筑与桥面遮挡使用参考高度，不宣称与原版逐像素相同。
- 触发器、Tags 绑定、Events/Actions、TaskForces、TeamTypes、ScriptTypes、胜负和战役进度当前只保留并统计，不执行。报告中的 `script_runtime`、`complete_campaign` 和 `complete_skirmish` 均为 false。

## 开源参考

参考 [OpenRA 的建筑中心与占地模型](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/Traits/Buildings/Building.cs) 区分占地原点、中心和美术偏移；参考 [OpenRA RA2 建筑序列](https://github.com/OpenRA/ra2/blob/master/mods/ra2/sequences/allied-structures.yaml) 核对剧场文件、损坏状态和附加层。参考用于确定工程边界与坐标关系；当前产品为本项目 C17 实现，没有引入 C# 或 C++ 引擎运行时，也未直接套用尤里的机器地址。
