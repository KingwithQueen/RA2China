# 格式与接口约定

## 所有权与只读边界

所有拥有资源的结构首次使用前必须清零，复用前调用对应 `close`。失败不会把半成品交给调用方；错误信息通过 `ra_error` 返回。

Windows 使用只读文件映射，打开权限为 `GENERIC_READ`，映射权限为 `PAGE_READONLY` / `FILE_MAP_READ`。库没有写文件、解包写盘、安装或打补丁接口。平台路径和来源名称使用 UTF-8，通过宽字符 Windows API 访问中文目录。

`ra_view` 是借用视图。`ra_mix_open` 不拥有传入字节，调用方必须让底层文件保持打开。VFS 拥有其挂载包的文件映射；从包读取的视图只在 VFS 保持打开时有效。散装文件映射由 `ra_resource` 持有。先关闭资源，再关闭 VFS。

INI 文档拥有其字符串，不依赖原始输入视图。MIX 和 INI 构建后可并发只读；VFS 的挂载/关闭不能与读取并发执行。当前没有创建线程，也没有宣称获得多核性能收益。

资源相对名称拒绝绝对路径、盘符、`.`/`..` 段、尾随点/空格和 Windows 通配符。挂载目录本身由调用者信任；这不是针对目录联接/符号链接的权限沙箱。

## MIX

以小端整数逐字段读取，不将输入缓冲区强制转换成打包结构体。

- 旧式头：16 位条目数、32 位数据长度、每项 12 字节的 ID/偏移/长度。
- 标志头：32 位标志；当前支持 `0x10000` 校验摘要、`0x20000` 加密头，未知标志报错。
- 加密头：80 字节公开密钥块，执行固定 320 位整数公共变换，得到 56 字节 Blowfish 密钥。头部以 8 字节块解码，数据区本身不解密。
- 有摘要标志时，验证数据区之后的 20 字节 SHA-1；摘要覆盖数据区，不覆盖包头。
- 条目必须完全落在声明的数据区中。不会把摘要或尾部字节当作条目数据。
- 为便于查询，内存索引按无符号 ID 排序；同 ID 多条目报错。不同条目允许共享数据范围。
- CRC32 模式与经典模式由调用者明确选择，不能仅凭旧式/新式头推断哈希算法。RA2 的默认选择是 CRC32。
- 不恢复未知文件名，不从哈希反推名称。枚举保留原始 ID，已知名称可直接查询。XCC 名称数据库的显示支持留待后续。

算法参考：现有项目的只读审计脚本 `H:\开发\研究资料\工具\audit_mix.py`、[OpenRA MIX 格式实现](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Cnc/FileSystem/MixFile.cs)与[XCC MIX 格式资料](https://xhp.xwis.net/documents/MIX_Format.html)。当前 C 实现未引入这些项目的运行库。

Blowfish 初始表是 π 小数部分的十六进制数学常量，已保存在源码中，构建时不需要生成。测试中的加密包为独立合成的 3 字节 `abc` 数据；不包含游戏美术或规则。公共密钥变换由独立的大整数参考结果核对，Blowfish 和 SHA-1 另有已知向量。

## 资源挂载

`ra_vfs_mount_mix` 接受 `archive.mix|nested.mix|another.mix`。各级索引验证完成后才将挂载加入 VFS；失败不会破坏已有挂载。嵌套包的数据直接借用顶层文件映射。

`ra_vfs_mount_directory` 挂载散装目录。每次读取按优先级查询：数值大者优先，同值后挂载者优先。资源不存在时回退；其他读取错误立即报告，避免把不可读的高优先级资源误当成不存在。

覆盖的是整个文件，不执行字段合并。当前优先级是本引擎的明确规则；还未声称逐项复现 RA2 对所有 `expand` / `ecache` / 地图覆盖文件的自动发现与加载顺序。

Windows 文件系统提供散装文件名称大小写匹配；MIX 按 ASCII 大写后的名称计算哈希。非 Windows 平台目录查询沿用宿主文件系统行为，尚未执行平台验证。

## INI

`ra_ini_parse` 默认使用兼容模式；`ra_ini_parse_ex(..., RA_INI_STRICT, ...)` 用于严格检查。

共同规则：

- 处理 CRLF、LF、CR；记录原始行号。
- `;` 为行内注释起点，包括引号内部；引号不是转义语法。
- 在第一个 `=` 处分割键和值，值内其他 `=` 保留。
- 去掉节名、键和值两端的 ASCII 空白。
- 允许空值与只含注释的空配置。真实 `mpsiege.ini` 即为占位配置。
- ASCII 大小写不敏感查找；保留源文件拼写、所有节声明与所有赋值的原始顺序。
- 同节同键重复定义保留全部记录，查询采用最后赋值，并累计重复数量。
- 节名不能为空、节头必须闭合、键不能为空，赋值必须位于节中。
- 不展开 include、变量、继承或多行值；不解释任何游戏行为。

兼容模式另外处理原始规则中实际存在的裸说明文字，以及 `[MirageWH] // ...` 一类节头尾部说明：保留文本/行号诊断后继续解析。严格模式拒绝这些内容。`//` 不作为通用行内注释，因而不会损坏值中的 URL/路径。

文本编码：

- UTF-8 BOM：去除 BOM，并验证 UTF-8。
- UTF-16 LE/BE BOM：验证代理对并转换成 UTF-8，拒绝未配对代理项和嵌入 NUL。
- 无 BOM：有效 UTF-8 标为 `utf-8`；否则标为 `bytes`，逐字节保留。不会自动猜测 GBK/Big5，也不会用替代字符改写数据。
- 命令行输出非 UTF-8 的旧编码字节时，将高位字节表示为 JSON `\u00XX`；这是可恢复的字节表示，尚不作为最终中文显示解码。

整数转换为十进制 `int64_t`，检查溢出和尾部垃圾；布尔转换接受 yes/no、true/false、on/off、1/0。百分比、速度、距离、游戏帧单位以及对象引用将由后续规则层解释。

这些约定已经用真实文件验证可读性，尚不等价于完整原版 INI/规则行为兼容。
