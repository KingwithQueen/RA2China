# 原版 1.006 最小战场（第六阶段记录）

当前程序已进入第七阶段：速度换算、独立转向、攻击、炮弹、伤害、摧毁和回放协议均已更新。当前用法与边界以 [移动校准与最小战斗](移动校准与最小战斗.md) 为准，以下保留第六阶段的历史设计和验收范围。

本阶段在新目录使用 C17 实现可交互的移动小场景。资源来自原版 1.006，未启动或修改旧游戏。中国内容未启用。

## 启动与操作

运行 `build/ra2battle.exe`。默认加载 `MP05MW.map`；下拉框可切换原版地图。左键点选坦克、拖框多选，Shift 加选，右键下达移动命令。中键拖图、滚轮缩放，Home 回到测试单位。空格暂停/继续，单步按钮或 F10 推进一个模拟步。重新开始会清空命令。

F5 保存 `.rpl` 回放，F9 读取。读取前先选择相同地图；地图、规则、通行数据或初始单位不一致时拒绝加载。命令在下一模拟步执行，暂停时刚下达的命令需先单步或继续，才能保存最终状态。回放期间禁用新移动命令，结束时自动暂停并显示状态摘要比较结果。重新开始可恢复操作。

通行层按钮显示绿色可通行、红色不可通行。单位仍会占格；不可到达的合法地表目标会等待并定期重试，不瞬移到目标。多选移动为每辆车分配目标附近的不同空格，目前没有完整编队、拥堵消解或全局交通协调。

可指定原版资源目录或初始地图：

```powershell
.\build\ra2battle.exe --original 'H:\开发\运行版本\原版1.006' --map MP13DU.map
.\build\ra2battlecheck.exe --map MP05MW.map --output 'D:\Program\红色警戒2\build\测试.rpl'
.\build\ra2battlecheck.exe --map MP05MW.map --replay 'D:\Program\红色警戒2\build\测试.rpl'
.\scripts\verify-battle.ps1 -AddressSanitizer
```

## 单位与地图通行

- 测试单位为两辆灰熊 MTNK、两辆犀牛 HTNK，位于地图路径点零附近的有效陆地。没有路径点时使用稳定的替代中心搜索。测试单位不替代或执行地图中的任务对象。
- MTNK 按原版 `Image=GTNK` 读取模型，不递归套用其他单位的 Image。真实 VXL/HVA/VPL、调色板与车体/炮塔/炮管合成复用第四阶段代码，预计算八个朝向，当前统一使用 unittem.pal。测试中可同时操控两种阵营的车辆，尚无敌我战斗关系。当前缩放和朝向显示是小场景预览，不承诺原版逐像素、阴影或精确模型尺寸。
- TMP 的地表编号必须先转换：9 为水，10 为岸边，11/12 为道路，15 为悬崖；不能直接作为规则 LandType 数组下标。原始 TMP 值仍由解析器保留。
- 对应地形的 `Track` 百分比决定履带车速度；矿石覆盖物使用 Tiberium 地表速度。水、岸边、悬崖、墙、缺失地形和局部地图边界不可通行。
- 建筑按原版美术 `Foundation=宽x高` 阻挡；无法识别的 Foundation 保守阻挡一个格并计数。地图既有地物、车辆、步兵作为静态障碍。树木占格目前按单格保守处理，尚未实现原版剧场占格位图、碾压和障碍破坏。
- 相邻格高度差大于一禁止跨越；高度变化需坡格。斜行同时检查两条正交路线，禁止切墙角。精确坡向和坡面运动仍需原版对照。
- 车体出发格与下一格同时保留占用，抵达后释放出发格；稳定单位编号决定提交顺序。不执行单位互换或相互穿过。
- 桥面/桥下多层路径尚未建立，检测到的桥覆盖物明确阻断。地形隧道也不代表已实现入口/出口传送；悬崖与地图对象仍约束普通地表路径。
- 建筑、覆盖物及地图中既有其他对象继续使用第五阶段位置标记；当前四辆测试坦克为实际单位图像。未接入战役脚本、敌方 AI 和原地图单位行为。

地表字段转换参考原格式研究者对实际 TMP 的观察记录，并用原版水、岸边、悬崖格及窗口截图核对；这不是用 YR 的固定地址驱动新引擎。[TMP 地表编号原始研究讨论](https://ppmforums.com/topic-39611/all-tile-type-ids/)。

## 模拟与回放约定

`include/ra2/battle.h` 是独立整数模拟接口。地图接入、资源绘制和窗口位于 `battle_scene`、`battle_viewer`，不进入模拟核心。

| 项目 | 当前约定 |
|---|---|
| 模拟频率 | 固定每秒 15 步；墙钟微秒换算保留余数，不按绘制次数推进 |
| 坐标 | 一个格 65,536 个整数单位；直行距离 65,536，斜行距离 92,682 |
| 速度 | 原版 Speed × 4,096 / 步，再乘目标地形 Track 百分比；这是待原版计时校准的参考换算 |
| 命令 | 执行步、严格递增序号、稳定单位编号、目标格；先处理该步命令再更新单位 |
| 寻路 | 有权 Dijkstra、固定邻居顺序、相同距离按格号打破平局；64 位路径代价 |
| 动态阻挡 | 重新寻路；失败后等待固定步数重试，重试次数进入摘要 |
| 随机数 | 本阶段没有随机行为，不消费随机数；未来机制须显式引入版本化随机状态 |
| 摘要 | 明确小端序逐字段序列化，SHA-1；包含内容指纹、地形、类型、模拟步、路径、单位状态和已执行命令数 |
| 回放 | `RA2RPL6`、格式/模拟版本、频率、内容与初始状态摘要、初始单位、命令、结束步、最终状态摘要、全文件摘要 |
| 上限 | 512×512 格、64 单位、8 种移动类型、16,384 条命令、单路线 4,096 格、1,000 万模拟步 |

摘要不包含选择、相机、显示帧率、指针或结构体填充。占用表由单位状态推导，寻路工作缓冲不参与摘要。尚未执行的命令不计入当前状态摘要；完整回放文件另有摘要覆盖全部命令。

回放先检查长度、摘要、版本、内容、初始单位、命令范围和顺序，全部通过后才重置战场。无效文件不破坏当前状态。最终摘要不同会明确报错；SHA-1 用于复现检查，不提供签名认证。回放只适用于本引擎当前协议，不是原版存档或联机录像。

当前只有单线程模拟和寻路，建立了后续多核工作的对照基线；未宣称多核加速或完成了与原版 1.006 的运动学一致性。加速度、ROT 转向耗时、炮塔独立朝向、细分碰撞、海空、步兵子格、桥梁、碾压、战斗、经济、生产、AI、存档和联机仍属于后续阶段。

## 阵营与字段边界

类型注册使用稳定字符串阵营标识。内置 `ra2.allied`、`ra2.soviet`；`future.china` 保留且禁用，注册中国类型会被拒绝。未来内容可以通过类型/阵营接口扩展，不绑定第三阵营的某个原版数值。

当前消费的主要字段为 `Image`、`UIName`、`Speed`、各地表 `Track`、覆盖物 `Wall`、美术 `Foundation`。`MovementZone=Destroyer`、Locomotor GUID、ROT、Accelerates、Crusher、TooBigToFitUnderBridge 等仍保留在 INI，但尚未执行对应机制。不能将本阶段少量运行字段的完成扩展为整个规则对象已经可运行。数值和平衡不写回原文件。

## 验证入口

正式结果见 `reports/latest-battle.json` 指向的 `validation.json`。包括整数模拟测试、三剧场真实窗口选择与移动、独立进程命令回放、所有 131 个原版地图条目的通行构建、内存检查，以及原版五个输入包 SHA-256 和旧项目完整文件清单的前后比较。原有地图缺失引用继续保留，不修补原件。

下一阶段先对照原版移动计时、转向、坡道和停靠；再加入最小战斗与音效，逐步建立建造、生产、采矿和胜负闭环。AV1 / HEVC 的比较安排在媒体阶段，未引入到本阶段构建依赖。
