问题包括未提供文件的 `hyte`、`Mclif`、`MDrods` 名称、超出剧场范围的编号和空子块引用。报告逐格列出坐标、编号、子块与具体原因；查看器标成洋红色，不修补地图、不猜测替换。

原文件未包含可恢复文件名的条目用 MIX 哈希标识，不能据此猜测它们的正式游戏用途。已确认问题以包名、地图摘要和数量登记在 `tests/known-map-issues.json`。正式验证拒绝新增或变化的问题，独立程序也重新计算了缺失引用。

## 验证内容

- 新增 C 边界测试 2,028 项全部通过，覆盖 LZO / LCW 指令类别、重叠和远距离复制、截断、输出长度、TMP 完整字段与逐字节截断、越界尺寸、数字行重排、重复键、非法 Base64、结束坐标、负路径点、节外参数和默认地表。
- 独立 Python 程序只使用 MIX 索引接口取得成员位置，自行解码地图数据和 TMP；不调用 C 地图或压缩解码器。两套预设均核对 127 份不同地图的四类压缩段、每个 TMP 的字段范围与统计，以及 2,227 个地形格样本。全部一致。
- 原生窗口的 44 项检查全部通过：通过控件消息切换两套预设、三张实际地图和三份 TMP，检查资源来源、图层、缩放、拖动、失败保留、导出，以及中文路径、非法 Unicode 和超长路径，并保存 9 张窗口截图。
- Release 的五组单元测试及 CMake/CTest 的五组测试全部通过。AddressSanitizer 对新增单元测试、完整中国资源预设和同一套原生窗口交互检查通过，严格模式按预期以退出码 2 报告现有缺失引用。具体结果和日志保存在正式报告目录。
- 14 个输入文件的 SHA-256、大小和修改时间前后一致；旧项目 51,052 个文件的路径、长度和修改时间清单前后一致，检查覆盖正式验证运行时段。

这些结果证明地图数据、实际地形绘制和查看器交互可用；不代表旧游戏运行验收、战场模拟、原版画面逐像素兼容或多核性能通过。建筑和单位当前显示布局位置，完整战场美术组合仍需后续实现。
