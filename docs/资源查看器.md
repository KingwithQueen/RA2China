# PAL、SHP、CSF 与资源查看器

产品代码为纯 C17，窗口使用 Win32/GDI 和 Windows 中文字体，不依赖 Python、.NET、C++ 或外部图像库。新增注释使用中文，遵循《编码规范》。

## 打开和操作

双击 `D:\Program\红色警戒2\build\ra2viewer.exe`。默认读取 `H:\开发\运行版本\原版1.006`，并叠加 `H:\开发\运行版本\中国开局验证`。默认显示解放军图像和 `Name:CNPLA` 中文文本。首次切换资源集需要完成只读包校验；成功加载的资源集会缓存。

- 在“资源集”切换原版 1.006 和中国 MOD。
- 在“文件”选择已知 SHP/PAL；也可手动输入资源名称后点“读取”。下拉目录只列出当前确实存在的资源。
- 使用上一帧、下一帧、帧号跳转和播放查看图像；界面帧号从 1 开始，库接口从 0 开始。
- 选择适合窗口或 1/2/4/8 倍缩放。大画布在适合窗口模式按比例缩小。
- 在“调色板”选择实际 PAL 名称后重新读取。单位通常用 `unittem.pal`，雪地单位用 `unitsno.pal`，图标用 `cameo.pal`，动画按资源要求选择 `anim.pal` 等；当前不会从美术规则自动推断调色板。
- 直接读取 `.pal` 可以查看 16×16 色表。
- 右侧可按 CSF 标签或中文内容搜索；选中条目后在下方查看、复制完整文本。简体和繁体保持源文件原文，不做自动转换。
- “保存图”把当前窗口的资源、帧号、文本及来源保存为 BMP，位置由保存对话框选择。不会写回资源。

例如选择 `pla.shp` 配 `unittem.pal` 查看解放军；选择 `plaicon.shp` 配 `cameo.pal` 查看其图标。`ls800cnpr.shp` 是 800×600 的加载图，可测试大画布缩放。

其他目录可通过 `--original <目录> --mod <目录>` 指定。该预设要求原版 `ra2.mix`、`LANGUAGE.MIX` 和指定中国目录的 `ecache91.mix` 存在；不是通用 MOD 自动发现器。可重复验证使用 `--self-test <已存在的输出目录>`，自动检查会短暂显示窗口但不抢占输入焦点。

## 接口和所有权

公共接口在 `include/ra2/assets.h`。拥有型对象首次使用前清零，成功打开后关闭再复用。解析失败不会发布部分结果。

| 接口 | 输入与输出 |
|---|---|
| `ra_palette_parse` | 768 字节 PAL 转换为 256 个 RGB 颜色，输出不借用输入 |
| `ra_shp_open` | 校验帧表与全部图像数据，拥有帧元数据，借用原始字节 |
| `ra_shp_decode` | 按需输出完整画布索引，不修改 SHP，可用独立缓冲并发解码 |
| `ra_csf_parse` | 拥有标签和 UTF-8 文本，附加字节仍借用原始资源 |
| `ra_csf_get` | ASCII 大小写不敏感查询，重复标签末次生效，原始条目仍保留 |
| `ra_shp_close` / `ra_csf_close` | 释放拥有数据；再关闭资源和 VFS |

CSF 文本包含长度，可保留内嵌零；查看器以可见符号替代零字符显示。附加值按原始字节及长度保留，不猜测代码页。空标签值和一标签多值均可解析。

## 格式支持边界

PAL 为 RA2 的 256×RGB 六位分量，严格要求 768 字节和 0..63 范围；显示扩展采用 `(v << 2) | (v >> 4)`。不把其他八位 PAL 变体静默当作 RA2 调色板。

SHP 仅支持 TS/RA2 格式：8 字节文件头、24 字节帧头、裁剪偏移、原始索引和按行零游程。按低位标志判断是否压缩，保留完整 32 位字段；原版的部分高位有编码器遗留值。索引零的透明显示遵从帧标志，裁剪区域之外显示棋盘底。按原始 PAL 预览，不叠加游戏中的阴影、阵营色、光照或建筑多动画。

安全检查包括帧表、数据偏移、下一不同帧边界、画布范围、行长度、游程完整性和缓冲容量；单帧画布上限 64 Mi 像素。允许共享帧数据、零偏移空帧和 `null.shp` 零尺寸占位。原版常见的行尾透明游程超宽只在行末截断，记录 `clipped_zero_runs`；省略的透明尾部补零，记录 `short_rows`。行中越界、游程缺字节和零长度游程仍拒绝。

CSF 支持版本 2/3、语言编号、标签计数、`STR`/`STRW`、按位反转 UTF-16LE、代理对及附加数据。拒绝不配对代理项、非法块、截断、计数不符和尾部多余字节。标签限 ASCII，文本保持 Unicode。当前不写入 CSF，不合并多个 CSF 文件。

## 挂载和名称目录

原版按递增优先级挂载 `ra2.mix` 内的 cache、conquer、generic、local、temperat、snow、urban，再挂载 LANGUAGE 内的 cameo 与直接成员，最后挂原版散装目录。中国预设增加 `ecache91.mix` 和中国散装目录，后者最高优先级。每个成功资源保留实际来源。

不挂载视频包，不绕过已有摘要错误。多次挂载同一个顶层 MIX 当前会重复校验并建立只读映射，首次打开的耗时仍有优化空间。没有实现异步资源任务系统。

名称目录来自既有提取索引及已确认的 10 个中国资源名称，包含 726 个名称，不携带原始资源。无法凭 MIX 哈希还原所有未知名称；未列出的有效资源可以手动输入其名称。

## 验证入口与格式参考

`scripts/verify-assets.ps1` 运行 C 单元测试、两套实际资源、全部图像帧、全部 CSF 文本、原生按钮检查和窗口截图，保存 6 个实际输入的 SHA-256、大小与修改时间前后对照。`ra2assetcheck` 的 `--samples` 在报告中保留少量抽样原始字节供独立参考解码，不修改源资源。Python 脚本仅是第二份验收实现，产品与 C 单元测试不依赖它。

格式事实参考 [XCC 的 SHP 解码实现](https://github.com/OlafvdSpek/xcc/blob/master/misc/shp_decode.cpp)、[XCC 的 CSF 实现](https://github.com/OlafvdSpek/xcc/blob/master/misc/csf_file.cpp)、[OpenRA 的调色板读取](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Game/Graphics/Palette.cs)。本项目按字节布局独立编写 C 解析器，没有引入这些 C++/C# 库。

本窗口继续用于 PAL/SHP/CSF。第四阶段另有 `build/ra2voxelviewer.exe` 读取 VXL/HVA/VPL，详见《体素预览》。资源验证不表示战场渲染、游戏行为、旧存档或多核性能已经完成。
