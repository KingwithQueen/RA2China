# 损坏桥梁、摧毁修复与坠桥

本阶段在 `D:\Program\红色警戒2` 延续纯 C17 实现，仅使用原版 1.006 的规则、地图与图像作为输入。中国阵营继续只保留禁用的 `future.china` 接口。旧项目、原始资源及另一个对话中的中国设计文档不由本阶段修改。

## 当前实现

`battle_bridges.c` 管理高架混凝土桥、高架木桥、低木桥和低混凝土桥的桥段状态。高桥宽三格，桥面与桥下分别占格。高桥的原始 0–17 帧均可表示；受击从完整或局部损坏状态进入 6/15 帧，再次成功受击移除桥段。邻段按桥向更新 4/5、7/8 或 13/14、16/17，两个方向的编号顺序并不相同；相邻悬空残段会继续移除。已经移除的桥段仍保存位置、材质、方向和原有地表，供修复与回放使用。

初始地图中若有相向的断口（X 向 8→7，Y 向 16→17），且中间地图格连续、同高、无其他桥段冲突，会登记最多 128 格的缺失段。缺失段初始不通行、不绘制完整桥面；修复事件可以恢复贯通。不能安全推断的桥形继续阻断，不凭空连接高度不同或互相冲突的桥。

低桥按原始 01–28 编号识别，在地面层工作。普通直段先进入 07/16，再进入 27/28 的断裂状态；岸边段的完整/损坏配对为 19/20、21/22、23/24、25/26。低桥截面三格同时改变，断裂后阻挡坦克；不能把桥下原有水面永久变成道路。修复时保留已知的原始完整贴图变体和岸边方向。

武器撞击已经调用桥梁判定。读取 `[CombatDamage] BridgeStrength=1500`、弹头 `Wall` 和规则指定的 `IonCannonWarhead`。普通受击从原版 R250 拒绝采样路径抽取闭区间 `[1, BridgeStrength]`，只有抽取值严格小于伤害值才成功。IonCannonWarhead 指定的特殊弹头跳过随机门限；它不等于按名称写死的 C4 或普通拆除弹头。高桥还要求撞击高度满足：

```
基底高度 * 104 + 208 < 撞击 Z <= 基底高度 * 104 + 520
```

不合格的高桥撞击不会消耗桥梁随机数。普通弹头不会使用单位生命值的累积扣血模型来代替这项规则。

## 单位、占格与弹体

撤销桥面时，使用单位当前轨迹的实际物理格与层号判定对象。桥上的当前坦克在同一步摧毁，记录出事格、出事高度和坠桥标志；清理当前占格、下一格、曲线预占、目标与任务队列，摧毁计数只增加一次。桥下地面单位独立保留，空中/离场对象不按桥面坦克处理。随后的修复不会复活死单位。

这一处理对照原版 `473000` 的桥面对象链：以当前生命值作为伤害量，距离为零，并设置忽略防御和禁止乘员逃生两个参数。当前实现完成的是最小战场坦克的坠桥结算；没有把尚未校准的抛落、入水、残骸或乘员动画加入模拟。

只预占了前方断桥格、但实际仍在岸边的车辆不会被当作桥上车辆摧毁。其已提交轨迹被撤销，在当前实际格归中后重新寻路。该归中策略是确定性参考行为，其与原版连续轨迹中断后的亚格位置差异列为实机待验项。未提交的缓存路径也会失效。弹体继续按当前桥况检查桥底与桥面；已经消失的桥面不再产生虚假的平面碰撞。

## 修复接口与查看方式

新增三个按固定步排序、可回放的场景事件：`RA_EVENT_BRIDGE_HIT`（已经通过外部判定的结构受击）、`RA_EVENT_BRIDGE_DEMOLISH`（强制移除目标直段，岸边段按损坏配对转换）、`RA_EVENT_BRIDGE_REPAIR`（关联整桥修复完成）。通过 `ra_battle_bridge_event_add` 提交，命令的单位编号为零，目标为桥段物理格。

这是提供给任务触发器、工程师与桥梁维修屋系统的模拟接口。目前没有工程师进屋、维修屋归属、占领或费用系统，因此没有添加破坏原版鼠标键盘习惯的免费修桥快捷键。实际玩家操作仍使用前阶段的原版输入约定。

可观看带固定时间事件的演示：

```powershell
Set-Location 'D:\Program\红色警戒2'
.\build\ra2battle.exe --bridge-demo
```

演示采用原始 `MP06T2.map`：6 秒损坏，12 秒断裂并结算桥上坦克，20 秒修复，岸边坦克随后过桥。可使用现有暂停、单步、重新开始和回放按钮。桥面、断口、修复图像和鼠标命中区读取当前模拟状态；低桥也使用原始 SHP。图像合成仍沿用最小战场的图层绘制，原版逐像素栏杆遮挡和桥口画面对齐仍待实机校准。

## 确定性与证据边界

仍采用每秒 15 个固定模拟步，不把它宣称为原版任意速度档的实时时间。模拟版本为 **7**，回放标识为 **RA2RPL9**。初始地形和初始桥况单独保存；重新开始与读回放恢复初始状态。桥段材质、方向、原始地表、当前帧、变化步、拓扑修订、受击/摧毁/修复/坠桥计数、单位坠桥记录和弹头资格均进入规范化状态摘要。回放事件完整验证后才改变现场，版本 6 明确拒绝。

`scripts/reference-bridges.py` 在核对原版 `game.exe` SHA-256 后，隔离执行高桥结构受击、邻段帧转换、随机区间和伤害/高度边界；世界通知、显示和对象链由显式夹具替代。原版文件从未作为输出打开，产品运行不依赖原版机器码或 Python。

原版地图语料、自己的原生窗口测试、原版指令夹具是三类不同证据，均不能替代原版正在运行的整局。用户已说明暂时没有原版实机录像，本轮按“完成代码、单列实机待验项”推进。

## 原版实机待验清单

1. `MP06T2`、`MP18S3` 的三个横向车道，在桥口、桥面侧沿及正负半格边界的实际轨迹与碰撞位置；断桥瞬间仍在岸边但已预占桥格的车辆亚格停靠位置。
2. 两端残桥间的缺失段重建；长桥连续两处/三处断裂、局部岸边残段、相邻桥与高低交叠结构的传播和修复范围。
3. 普通 AP 弹头在桥面上下边界和相邻格落点的概率与连续随机消耗顺序；爆炸跨格、桥口 TMP 转换与低桥邻段传播的完整分支。
4. 工程师进入桥梁维修屋后的触发步、关联范围、单位消耗、维修屋被毁/占领分支。当前只有修复完成的模拟接口，这套玩家交互留给建筑/步兵系统。
5. 桥上坦克静止、转弯、连续停靠和发射中坠桥；水面/陆地、桥下有单位、发射者死亡后的在途弹体，以及残骸/入水动画。
6. 铁路桥、尚未确认的桥头边饰、特殊任务桥，以及步兵、舰船、悬浮/两栖单位各自的通行与碰撞规则；当前单位模型仍限于原版最小坦克战场。

没有这些实机记录前，不将本轮称为原版所有桥梁场景的完全一致复刻。下一阶段先收敛上述桥梁场景，再进入建筑、工程师与经济闭环；多核拆分继续以固定步和逐步摘要一致为前提。

补充回归覆盖桥面撤销后索敌资格的变化：保留的桥位用于修复，候选过滤只把仍存在的桥面当作分层遮挡。多点路线在实际执行时再次验证整批目标；若断桥使其中一点失效，整批拒绝并保留旧任务，不能把后续追加接到旧路线。

正式验收中，正常版桥梁场景各运行 900 步；内存检查版覆盖全部损坏、断裂、修复和抵岸事件的 600 步，并与正常版相同前 600 步的状态链交叉比较。原始断桥穿越另逐步核对 600 步，单元回放夹具仍保留长跑。`ra2battlecheck --steps N` 可指定录制步数；不能早于尚未执行的命令，读取回放时也不能改变文件记录的结束步。
