# 连续弯道与坡向通行

本轮在 `D:\Program\红色警戒2` 继续实现纯 C17 最小战场。原版 1.006 是行为和资源基线，中国内容仍只有禁用的 `future.china` 扩展位置。旧项目、原始文件、历史报告和上一轮程序保留。当前验收入口为 `reports/latest-locomotor.json` 和 `reports/latest-battle.json`，上一轮 `latest-physics.json` 保留历史含义。

## 连续转弯

`battle_tracks.c` 使用原版普通履带的六组数值轨迹和 64 项方向控制，支持直行、45 度和 90 度弯道及其镜像。行进坐标和车体朝向沿采样连续变化，弯道可跨两段路径；在原版跳接位置进入下一条弯道的入口采样，避免每段返回格中心再原地转向。超过支持角度的改向保留原地转向。短距离倒车、矿场倒入、建筑出口等专用轨迹不在普通坦克路径中启用。

速度按原版七分采样余量推进，余量插值保留原版先存入 float 再向零截断的顺序。不能用理想曲线弧长或直接格长插值替代。速度系数仍使用上一轮的软件二进制数值运算；固定模拟状态不依赖宿主浮点设置。转弯状态、采样索引、余量、占格和跳接次数均进入摘要。显示方向从八向提高到 32 向，继续实际绘制原版车体、炮塔和炮管。

预先检查并保留曲线实际穿过的格子，避免绕过碰撞检查；途中改变目的地或停止时先完成已提交的曲线。抵达和摧毁释放预留格。当前占格策略仍是本项目的确定性保守策略，不能据此宣称复现原版交通仲裁、挤车、碾压和所有停靠情况。

数值表由 `scripts/generate-drive-tables.py` 只读生成，原版轨迹位于 `0x7a00a0`，方向控制位于 `0x7a0180`，坐标镜像方法为 `0x4a4740`。产品只编译数值表和 C 实现，不加载或执行原版机器码。

## 地面坡向连接

原版 `0x4c8730` 在普通地面层跨一层高度时，要求较低的格子带有坡面。上坡要求出发低格有坡面，下坡要求抵达低格有坡面；较高一侧单独有坡面不能替代。旧实现只要求任意一侧有坡面，现已修正。

全部 20 种坡面、八个行进方向、源和目标坡面组合以及高度差 -2 至 2，进行了 17,640 组原版隔离指令对照。坡面朝向和截顶高度继续使用已对照的 20 种实际高度平面；普通地面通行函数没有额外按坡面编号施加未经证实的朝向掩码。斜向移动仍检查两条正交通道，避免穿墙角。

此处的完整覆盖指普通地面坡面连接。桥面和桥下的独立层、桥头转换、水陆两栖、飞行及坍塌地形仍未实现，地图中的桥梁继续明确阻挡。未知坡面不会被当作有效斜坡放行。

## 威胁评分、炮口和伤害

自动警戒、移动攻击和巡逻改用普通坦克的威胁评分。消费原版 `DumbMyEffectivenessCoefficient`、`DumbTargetEffectivenessCoefficient`、`DumbTargetSpecialThreatCoefficient`、`DumbTargetStrengthCoefficient`、`DumbTargetDistanceCoefficient` 和 `SpecialThreatValue`。评分考虑双方装甲适应性、对方当前攻击目标、特殊威胁、剩余生命比例以及超出武器射程的距离。相同分数以稳定编号取先者。1,600 组夹具直接调用原版 `0x6d7550` 比较数值。

该实现覆盖当前普通坦克的基础评分分支。原版完整 GreatestThreat 的扫描格顺序、全部候选过滤、AI 智能分支、阵营仇恨、隐形/空中目标、副武器选择及扫描时机仍待实现；不把单项评分相等说成完整索敌结果相等。

灰熊和犀牛从原版 `art.ini` 读取 `PrimaryFireFLH=150,0,100`，灰熊沿规则的 `Image=GTNK` 映射。发射位置使用原版 32 向平地矩阵和 float 截断顺序，替代原来的格中心加固定高度。1,052 组方向、边界角度和偏移组合与原版 `0x6c1830` 的平地矩阵路径对照。非零 `TurretOffset` 明确拒绝；底盘倾斜、后坐、侧翻及坡面动态矩阵尚未接入。

常规范围伤害移除额外四分之一格半径，按三维距离判断 `CellSpread` 的整数 lepton 范围，使用原版 float `PercentAtMax` 插值、先截断距离伤害再乘 `Verses`、向零截断及 `CombatDamage.MaxDamage` 上限。零结果不强制改成一，`MaxDamage=0` 也保持零。范围上界包含等于半径的位置，超出一个 lepton 即不伤害；原版当前伤害区域路径排除发射者。数值参考为 `0x47e1c0` 及其外层范围门限。

例如原版 AP 半径为 76 lepton，Damage=65、PercentAtMax=.5、Verses=100% 时，距离 0、1、75、76、77 的结果为 65、64、32、32、0。不同装甲、低伤害、零结果和最大伤害均有边界回归。

**伤害数值路径与碰撞落点分开验收。** 当前弹体碰撞仍使用原有的细分线段模型，普通直线弹体也是最小参考实现；完整原版弹体引信、近炸、目标命中判定、建筑、多层桥梁、穿透和特殊战斗效果没有因此完成。新的伤害函数会如实反映当前落点偏离造成的衰减，不能把“每发固定满额伤害”当作原版金值。

## 回放与验证

固定模拟继续为每秒 15 步，这是新引擎的参考步频，尚未建立原版游戏速度档位映射。回放标识仍为 `RA2RPL7`，模拟与数据版本升为 **5**。新增规则、炮口、伤害上限和全部曲线状态进入规范化摘要。版本 4 回放在改变现场前明确拒绝，旧程序与源码保留在 `build/stage9-preserved`。

`tests/locomotor_test.c` 覆盖支持的各方向曲线、连续跳接、曲线中停止和摧毁、全部坡向连接、新字段摘要敏感性及 600 步不同墙钟分组回放。既有 1,200 步物理回放保留。`scripts/reference-locomotor.py` 只读原版隔离执行数值参考；依赖只用于验证，不参与产品运行。固定地址读取先校验原版 SHA-256：`fe67fdac5073530a79baec14c4e072b5e7e4c0c462cee9659870c5330e9e6e3e`。

运行：

```powershell
.\build.ps1
.\build\ra2battle.exe
.\scripts\verify-locomotor.ps1 -AddressSanitizer -ConcurrentDesignDirectory 'H:\开发\研究资料\中国阵营重设计'
```

原生窗口自测实际创建战场、派发鼠标和键盘消息并保存画面；这属于新程序的操作验证。原版指令隔离比较、独立进程回放、内存检查和完整原版游戏实场景验收是不同证据，报告分别记录。原始输入七份 SHA-256、旧项目全文件清单以及已授权并行设计文档差异均保留。

下一步先建立原版实场景轨迹和碰撞落点的时间序列，补齐完整候选过滤与坡面底盘矩阵；再进入建筑、生产、采矿、电力、科技和胜负闭环。经济闭环稳定后以逐步摘要相同为前提分解并行工作。音效、FFmpeg 与 AV1/HEVC 高画质比较继续在媒体阶段处理。

正式记录位于 `reports/locomotor-20261019-final`，总交付审计为 `delivery.json`，游戏行为记录为 `validation.json`，CMake 记录为 `cmake.json`。
