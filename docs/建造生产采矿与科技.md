# 建造、生产、采矿与科技

更新日期：2026-10-20。主目标仍是原版 1.006 战役和单人遭遇战，菜单暂缓，中国阵营仍只保留未启用的 `future.china` 接口。

本阶段完成可操作的最小基地经济循环，使用纯 C17、原版规则、美术和地图。它是后续战役、遭遇战共用的模拟模块；当前入口为显式经济验证场，不代表完整原版战役或遭遇战已经完成。原来的 `--scenario` 仍按上一阶段载入原始场景，本阶段没有自动改写战役资金和脚本。

## 运行

程序：`D:\Program\红色警戒2\build\ra2battle.exe`。

- 苏军经济验证场参数：`--economy-demo --map MP17T6.map`。
- 盟军雪地验证场参数：`--economy-demo --allied --map MP32S8.map`。
- 可选原始资源目录：`--original "H:\开发\运行版本\原版1.006"`；默认即此目录。

开局提供所属国家的建造厂、一个坦克、10000 资金和科技等级 10。基地位置由原图中平坦、空闲且靠近矿藏的区域选出，矿藏完全来自地图，不额外添加。它没有遭遇战电脑对手、真实开局规则或胜负条件。没有创建 CMD/BAT 启动脚本。

侧栏左键开始建造或生产；同一车辆可排队。右键当前项目暂停，再次右键取消并退回已经支付的资金；左键暂停项目继续。建筑完成后左键侧栏项目，再左键地面放置；绿色占地可放，红色不可放，右键取消放置。原有左键选择与下令、右键取消、S 停止和编队等操作保留。

先建电厂、兵营、矿厂、战车工厂，再建雷达和作战实验室。矿厂放置后赠送对应矿车，自动寻找矿藏、采集、返厂卸货并继续；选择矿车后左键矿区可指定采集点，左键己方矿厂可要求部分载货返厂。矿车生命条下方的黄色条表示装载量。低电力会降低生产速度。

## 实现范围

| 系统 | 当前行为 |
|---|---|
| 建造 | 每家一条建筑队列；逐步付款、缺钱停工、暂停、取消退款、成品等待放置 |
| 放置 | 矩形占地、地图边界、同一平面、坡面、桥梁、矿藏、动态占格与所属建筑邻接检查；命令执行时重新验证 |
| 生产 | 每家一条车辆队列，最多 16 项；工厂出口有空位才生成，堵出口保留成品，资金不会重复扣除 |
| 新对象 | 建筑与车辆共用现有对象、生命、碰撞、选择、移动和攻击；稳定编号不复用 |
| 电力 | 实际存活建筑供电；电厂受损减少供电；原版低电力最小、最大速度和惩罚系数进入建造进度 |
| 科技 | Owner、TechLevel、直接前置建筑、POWER/FACTORY/BARRACKS/RADAR/TECH/PROC 通用前置组；检查实际所属和存活状态 |
| 采矿 | 原图矿种和密度、有限矿量、不同货物价值、矿车容量、指定采集/返厂、部分载货卸货、矿厂单车占用及摧毁后重新寻找矿厂 |
| 盟军矿车 | CMIN 正常驶向矿区，返厂可以传送到可用矿厂外圈；空闲落点和占格仍需通过检查 |
| 确定性 | 全部经济变化在固定 15 Hz 步中按稳定顺序处理；资金为 64 位整数，进度、矿量、载货、队列、停靠和新对象参与状态摘要 |
| 回放 | 保存初始对象与命令；运行时生产的对象由相同命令重新创建，重置恢复开局资金和矿量 |

已注册 18 个原版类型：灰熊、犀牛、武装采矿车、超时空采矿车，以及盟苏各自的建造厂、电厂、兵营、矿厂、战车工厂、雷达建筑和作战实验室。兵营与空指部目前作为建筑和科技前提，步兵、飞机生产尚未接入。

模拟版本为 **9**，回放为 **RA2RPL11**。旧版回放明确拒绝，不静默转换。版本 8 的源码、文档、程序与静态库保存在 `D:\Program\红色警戒2\build\economy-preserved`，其 EXE SHA-256 为 `c4f3268d9e8523f5d37785da96ec88caa8e123cde484590837a7e294ede8e571`。此前各阶段备份继续保留。

## 规则与资源证据

数据取自当前只读挂载的原版 rules.ini、art.ini 和地图；独立验收再与上一阶段保留且摘要相同的原始文件对照。Cost、BuildSpeed、BuildTimeMultiplier、TechLevel、Owner、Prerequisite、通用前置组、Factory、Adjacent、Power、Harvester、Storage、FreeUnit、Refinery、Dock、Teleporter、Riparius.Value 和 Cruentus.Value 已进入相应模块。建筑 Storage 目前只保留数据，尚未限制资源仓储。

建造基础时间按 `ceil(Cost × BuildSpeed × 60 × 15 × BuildTimeMultiplier / 1000)` 换算；随后受电力和可用资金影响。密度索引以 `index + 1` 表示剩余包数，逐包减少并移除耗尽的覆盖物；该映射和特殊矿种仍须原版实机进一步对齐。矿石、宝石使用原版 TIB01/GEM01 的 SHP 与专用 temperat.pal 调色板，矿车使用实际 HARV/CMIN 体素。没有生成或替换原始美术。

矿藏专用调色板也与 [OpenRA 的资源调色板配置](https://github.com/OpenRA/ra2/blob/master/mods/ra2/rules/palettes.yaml)交叉核对，避免把矿石绘成错误彩色像素。

本轮参考了 [OpenRA 的二代地图导入器](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Cnc/UtilityCommands/ImportGen2MapCommand.cs)、[RA2 地图资源分类](https://github.com/OpenRA/ra2/blob/master/OpenRA.Mods.RA2/UtilityCommands/ImportRA2MapCommand.cs)、[YRpp 的 RulesClass 字段](https://github.com/Ares-Developers/YRpp/blob/master/RulesClass.h)和 [Phobos 的采卸矿说明](https://github.com/Phobos-developers/Phobos/blob/develop/docs/Fixed-or-Improved-Logics.md#customize-harvester-dump-amount)。这些提供格式和行为参考；YR 的地址和行为不会直接套作 1.006 已校准结论。最终产品没有引入这些项目的 C++/C# 运行时。卸货已按整车一次入账处理，未把扩展中的分包卸货套入原版。

## 尚未完成或需要原版实机校准

- 原版生产阶段量化、国家/难度乘数、多个工厂加速与主工厂切换；当前使用规则时间和整数参考进度。
- 建筑展开动画期间的激活时机、非矩形占地、精确邻接边界、ExitCoord、工厂开门、驶出和集合点。
- 采集与卸货动画节拍：HarvesterLoadRate 可读取，全局缺省暂用五步；HarvesterDumpRate 的原版默认值、动画/卸货类 HORV、CMON 尚未逐帧校准。
- 矿厂实际 DockingCoords、精确朝向、内部停靠、多个停靠点与资源仓储容量；目前使用外圈落点和单车预约。
- 超时空矿车的传送准备、再出发延迟、动画、音效与原版寻厂细节；当前实现可用落点的瞬移参考行为。
- TIB2/TIB3 等遗留矿种的完整价值映射、矿藏生长、扩散、矿井补给、伤害/爆炸对矿藏的影响和原版矿区评分。
- PrerequisiteOverride、RequiredHouses、ForbiddenHouses、难度限制、特殊生产权限、建筑升级、售卖、维修、MCV 展开与重新打包。
- 步兵、飞机、舰船与高级单位生产，矿车武器/自愈的完整行为，以及 AI 经济、胜负、存档和联机。
- 当前总对象编号容量 512，不回收已销毁编号；适用于此阶段验证，长局需后续增加代际编号和容量管理。

本阶段没有把“解析到字段”算作完整玩法。原版 1.006 实机录像/逐步记录尚未提供，正式报告保持 `original_runtime_calibration=false`；原始场景、自动验证和原版实机对齐是三件不同的事。

## 验证与继续开发

正式入口：`scripts/verify-economy.ps1 -AddressSanitizer`；包括 15 组 C 测试、原版温带苏军/雪地盟军的完整建造生产采矿过程、逐步回放、普通版与内存检查版的回放字节对照、独立 INI/LCW 数据检查，以及桥梁和首关场景回归。探查模式 `--probe` 只用于排错，不计作逐步回放验收。

本次实际验收中，原版两场经济流程的逐步回放在普通版执行；内存检查版运行完整经济模拟并核对终态，同时执行 C 测试中的逐步回放。没有把探查模式算作原图逐步回放。最终调色板修复另外保留源码差异、程序摘要、画面复验和终态相同的证据。

结果保存于 `reports/economy-20261020`，正式通过后更新 `reports/latest-economy.json` 与 `reports/latest-battle.json`。原始 7 份关键输入前后摘要、旧项目文件清单、源码前后摘要和程序摘要均保留。另一个对话对中国阵营设计文档的授权更新只记录，不回滚。

下一步补 MCV 展开、步兵和工程师、建筑维修/售卖与任务事件，再连通盟苏首关触发器、运输/登陆和任务胜负；随后补遭遇战真实开局、AI 建造与进攻。菜单继续暂缓，多核优化在确定性回放基线上逐项推进。

正式结果：`reports/economy-20261020/validation.json` 与 `delivery.json`，均为通过。最终普通版和 AddressSanitizer 版各 15 组 C 测试、35,333 项检查通过；干净 CMake/CTest 构建 15/15。原版温带苏军回放 6,897 步、雪地盟军回放 6,687 步逐步一致，共 13,584 对照步；桥梁另有 1,800 步回归，首关另有 30 步回归。最终普通版和内存检查版各完成两套原生经济流程，四份终态摘要均与相应完整回放相同，独立数据检查共 6,046 项通过。原图 ASAN 全程逐步哈希扩展检查没有计作完成。

两个基地均实际建成六座新建筑，赠送矿车并生产一辆坦克；苏军采矿入账 5000，盟军入账 9375。最后的三个源码差异只涉及矿藏调色板和验收输出，完整差异见 `display-only.diff`；反向还原的文件摘要与完整回放时的源码摘要一致。模拟模块未在回放通过后继续修改。
