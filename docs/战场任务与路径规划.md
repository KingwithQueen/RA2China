# 战场任务与路径规划

后续连续运动与弹道校准已进入回放版本 4；本页保留当时的阶段记录，当前行为和验证入口见[连续运动与弹道校准](连续运动与弹道校准.md)。

本阶段推进《原版操作与后续计划》的第一项，补齐现有两种坦克的战场任务。产品、工具和测试仍为纯 C17；旧项目与原始资源只读，中国阵营只保留未启用的 `future.china` 接口。本阶段没有开始建设、经济或多核加速。

## 运行与操作

在项目目录运行 `build/ra2battle.exe`，默认只读使用 `H:\开发\运行版本\原版1.006`。键位继续来自原版包内 `keyboard.ini`，共 89 项。

| 操作 | 已实现行为 |
|---|---|
| Ctrl+左键地面 | 接近到射程内后持续向地面开火，允许瞄准不可通行的实际地图格 |
| Ctrl+左键单位 | 强制攻击指定单位，允许友军；普通攻击仍拒绝友军 |
| Ctrl+Shift+左键 | 移动攻击：遇敌交战，目标死亡或脱离当前索敌范围后继续前往原目的地 |
| G | 以命令生效时的停靠格为警戒原点，发现来敌后接近并攻击；结束后返回原点 |
| X | 散开到附近能通过的空格；多个单位使用稳定编号依次选格，避开已选散开目的地 |
| 按住 Z、逐次左键地面、松开 Z | 规划并统一启动路线，每个单位最多 32 个路径点 |
| 规划时点击已有路径点 | 闭合为从该节点开始的巡逻；巡逻遇敌交战后恢复路线 |
| 规划时右键 | 取消选择并保留该组规划，可以继续选择另一组；松开 Z 同步提交各组路线 |
| S 或新移动/攻击/警戒/散开命令 | 替换旧任务，清除该单位原路线；S 清除所选单位尚未提交的规划 |
| 失去焦点、打开选项、重置或成功读取回放 | 清除尚未提交的规划，避免遗漏松键导致意外下令 |

规划路线显示为青色，已执行的所选单位路线为黄色，带节点编号及巡逻闭合线。路线上被其他单位占据的节点会保留并等待重新寻路，不会跳过。普通路线到达终点后清空，巡逻路线持续执行，直到改令或单位被摧毁。

原版语义依据为[原版官方手册扫描文本](https://manualmachine.com/gamespc/commandconquerredalert2/1117998-user-manual/)的 Guard、Attack Move、Forced Firing 和 Way Points 章节。实际默认键位以本机原版资源为准。完整节点编辑、DEL 删除节点、Alt 强制移动/碾压、Ctrl+Alt 指定护卫及完整原版鼠标图形尚未实现，不能算作原版全部操作复刻。

## 模拟、回放与接口

`src/battle_missions.c` 管理有序命令、原任务目的地、临时追击、警戒原点和路径队列。`battle_combat.c` 通过同一瞄准接口处理单位与地面目标。原任务目的地不再被临时射程圈寻路覆盖，击毁目标后可以恢复路线。所有任务仍由固定 15 步/秒的单线程参考模拟处理，不依赖墙钟、相机、选择状态或工作线程调度。

公共接口为 `ra_battle_order_add` 与 `ra_battle_waypoints_add`。后者先检查整个批次，再连续记录路径开始、追加、闭环命令；容量不足或目标无效时不写入部分路线。查看器对多个编队的松键提交也使用完整回退。每条命令仍是五个显式小端序 32 位字段。

回放继续使用 `RA2RPL7` 标识，格式与模拟版本升为 **3**。新增 Sight、任务目的地、警戒原点、地面目标、路径点、游标及循环起点参与状态摘要。读取时验证追加批次的连续性、单位、模拟步、长度及循环索引；完整验证通过后才替换现场。版本 2 明确拒绝，不静默转译。输入调整阶段的程序和相关源文件保存在 `build/input-stage-preserved`，旧回放和历史报告保留。

## 校准边界与紧接着的工作

当前最小索敌使用原版规则 `Sight`，两种坦克均从原文件读到 8 格；以距离、稳定单位编号选择敌人，警戒目标还需位于原点的 Sight 范围内。原版完整威胁评分、自动警戒/闲置索敌、阵营结盟、迷雾、追击半径和散开随机算法仍需独立校准。普通闲置坦克目前沿用此前受击还击机制，不能把 G 的实现当作完整 AI 已完成。

先前 58 组运动窄路径与 512 次随机抽取对照仍通过。本阶段另增加连续减速研究脚本 `scripts/reference-stop-chain.py`：严格验证原版可执行文件 SHA-256，在显式夹具中采集 64 次连续减速更新及速度查询，结果为 `reports/missions-20261019-final/native-stop-chain.json`。这不是原游戏完整运行验收。采样发现一个相对理想十进制速度的整数边界差异，C 端连续状态和完整移动轨迹尚待校准，不能据此声称现有减速完全等同原版。

下一轮仍完成计划第一项的剩余部分：先做连续停靠状态、完整转弯、坡向与弹道/伤害边界的独立原版对照，记录可重现的场景与误差，再进入建设厂、建造摆放、生产、矿车、经济、电力、科技和胜负。经济最小流程稳定后开始 1/2/4/8 线程的耗时与逐步摘要比较。AV1/HEVC 和中国内容包仍留在后续顺序。

## 验证入口

运行 `scripts/verify-missions.ps1 -AddressSanitizer -ConcurrentDesignDirectory 'H:\开发\研究资料\中国阵营重设计'`。用户已确认该目录的 Markdown 由另一对话编辑；仅记录并保留这些变化，其他旧文件与七个原版输入继续严格比较。

正式报告入口为 `reports/latest-missions.json` 和 `reports/latest-battle.json`。常规测试覆盖强制开火、友军伤害、交战恢复、警戒返回、散开、堵路等待、巡逻、容量原子性、无效回放拒绝及逐步摘要；温带 MP05MW、雪地 MP13DU、城市 MP29U2 各执行真实 Win32 窗口消息操作，并生成独立进程任务回放。AddressSanitizer 运行全部 C 检查和一个原生窗口样本。截图来自窗口实际像素，不是离线效果图。


## 本轮验收结果（2026-10-19）

正常 C 与 AddressSanitizer 分别通过 8,758 项检查，新增任务检查 399 项；CMake 8/8 通过。温带、雪地、城市各通过 108 项窗口操作及实际路线像素检查，合计 324 项；AddressSanitizer 窗口另通过 108 项。每种剧场的报告目录保存 10 张实际窗口 BMP，其中规划、巡逻和地面开火另提供 PNG。

三种原版地图各 900 步的新任务，录制与独立进程回放的最终状态及逐步摘要链全部一致，共核对 2,700 对模拟步。摘要链证据为 `reports/missions-20261019-final/per-step-traces.json`。测试目的地搜索产生的临时路径在样本录制前重置，避免把夹具查询当成模拟输入。原版 58 组运动窄路径与 512 次随机抽取仍一致；64 次连续减速采样是后续校准资料，不计为完整移动通过。

七个原版输入的前后 SHA-256 一致，旧项目结束清单为 51,066 个文件。已确认中国设计目录内 11 份 Markdown 的并行新增或修改如实保留，其他旧文件清单一致。本次写入均位于新项目。没有 Git 仓库、分支、提交或推送。

CMake 验证使用 Visual Studio 自带 Ninja，并设置 `CMAKE_POLICY_DEFAULT_CMP0141=NEW`、`CMAKE_MSVC_DEBUG_INFORMATION_FORMAT=Embedded`、`CMAKE_C_FLAGS_DEBUG=/Z7 /Ob0 /Od /RTC1`。早先 /Zi 的 PDB 管理器失败日志保留；当前通过日志为 `cmake-final-build.log`、`cmake-final-tests.log`。主构建仍为 `build.ps1`。

当前正式入口为 `reports/latest-missions.json`、`reports/latest-battle.json`，均指向 `reports/missions-20261019-final/validation.json`，简表为同目录 `final-summary.json`。先前测试调试产物保留，不能将历史失败文件当成当前结果。
